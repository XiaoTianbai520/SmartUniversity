**两个踩坑 + 解法（后续迭代必看）**：
1. **COURSE_ADJUSTED 必须传 `bizId = null`**。因为 `uk_notice_dedup(notice_type, biz_id, receiver_user_id)` 会让同一教学班的第 2 次及以后调整通知被唯一键吞掉。MySQL 唯一索引对 NULL 不去重，传 null 才能"每次调整都通知"。同时 T3 监听器用 `isNull` 查重在 bizId 为 null 时会误判为"已存在"而跳过插入，**已改为 bizId != null 时才查重**。START/END、WAITLIST_PROMOTED、SCORE_PUBLISHED 仍带业务 ID 正常去重。
2. **容量上调触发递补不能同步调用 tryPromote**。tryPromote 是 PROPAGATION_REQUIRED，在 `saveTeachingClass` 事务内同步调用会让共享事务被标记 rollback-only，导致教务改容量整体回滚。改成 `TransactionSynchronizationManager` 注册 `afterCommit` 回调执行。退课场景不受影响（本就该同事务原子完成）。
