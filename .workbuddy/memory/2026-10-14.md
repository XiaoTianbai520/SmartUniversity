## 诊断：§7.5 教学班成绩列表「未录入学生不返回」问题
- 现象：用户反馈前端调 7.5 拿不到未录入成绩的学生，无法手动补录/改成绩。
- 根因（代码已正确）：`ScoreServiceImpl.listTeacherScore` 以教学班全部 SELECTED 学生为基准返回，未录入学生 score=null/status=null 但必带 selectionId；首次调 7.4 保存即建成绩记录。后端无需改代码。
- 真正问题：接口文档 §7.5 说明写「只返回已录入成绩的学生」，与实现相反，误导前端丢弃 null 行。
- 已修正：`docs/接口文档.md` 与微信附件 `接口文档(2).md` 的 §7.5 说明/示例（两文件原只读，已清只读位后编辑）。
- 前端动作：渲染 null 行；补录/修改按钮用行内 selectionId 调 PUT .../scores/{selectionId}。
- 风险：若线上仍不返回未录入学生，说明跑的是旧构建，需重新构建部署当前源码。

## 追加（23:45）：返回不符文档的根因是全局 non_null 吞字段
- 用户指出现返回与 §7.5 文档不一致：文档写未录入学生 score/status=null，实际没这两个 key。
- 根因：application.yml 配 spring.jackson.default-property-inclusion=non_null（全局），Jackson 把 null 字段从 JSON 删除。代码(S-155/156)确实 set 了 null，但被序列化阶段吞掉。
- 修复：TeacherScoreRespDTO 的 score/status 加 @JsonInclude(ALWAYS) 覆盖全局，未录入学生现在显式返回 "score":null/"status":null，与文档逐字一致。已编译通过、细粒度中文提交 46840a2 并走 7890 代理推送(5406788..46840a2)。
- 待用户：用最新 master 重新打包部署，再调 7.5 即可见未录入学生带 score/status=null。
