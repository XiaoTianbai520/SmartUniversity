# 高校智慧教务选课平台 V1.2 + V2.0 新增接口清单

> **编号依据**：PRD Q1 决议 —— 已核实 `docs/接口文档.md` 的 §26~§33 全部为**非接口章节**（事务边界建议 / Controller 模块建议 / Service 模块建议 / 推荐 DTO 划分 / V1 核心接口优先级 / 已实现接口总览 / 后续版本接口预留 / 接口设计总结），§25「教师成绩统计接口」是最后一个业务接口章。因此**新增接口统一从 §34 起编号**，§26~§33 原样保留，不重排。
>
> **本文件作用**：V1.2 / V2.0 新增接口的字段级契约，供并行开发阶段各工作流直接使用；**最终由 T9 统一补录进 `docs/接口文档.md` §34 及之后章节**。
>
> **通用约定**：
> - 基础路径 `/api/v1`，统一响应 `{ code, message, data, timestamp }`；
> - 分页入参沿用现有 `PageQueryReqDTO`：**字段名为 `page`（默认 1）、`pageSize`（默认 10，上限 1000）**（与基础类字段名一致；旧文档笔误 `currentPage`/`limit` 已废弃，绑定以 `page`/`pageSize` 为准）；分页出参沿用 `PageResult<T>`：`{ records, page, pageSize, total }`；
> - 学生 / 教师身份一律由后端从 Token 还原，**任何接口不接受 `studentId` / `teacherId` 入参**；
> - 百分比类字段统一返回**数值本身**（如 `78.5`），不拼 `%`；学分 `DECIMAL(5,1)`；课时 / 人数为整数；
> - `non_null` 全局配置：值为 `null` 的字段不会出现在 JSON 中，DTO 中「可能为 null」的字符串统一初始化为空串。

# 34. 容量缓存与对账接口（V1.2）

> Controller：`AdminSelectionCacheController`（W1）、`AdminCacheReconcileController`（W2）
> 权限：`@RequireRole(RoleEnum.ADMIN)`

## 34.1 教学班容量计数预热

```http
POST /api/v1/admin/selection-batches/{batchId}/cache/warmup
```

**路径参数**

| 参数 | 类型 | 说明 |
|---|---|---|
| `batchId` | Long | 选课批次 ID，示例 `1` |

**返回 JSON**

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "batchId": 1,
    "teachingClassCount": 12,
    "warmupCount": 12,
    "failCount": 0,
    "mismatchCount": 0,
    "durationMs": 86
  }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `batchId` | Long | 批次 ID |
| `teachingClassCount` | Integer | 批次内教学班总数 |
| `warmupCount` | Integer | 成功写入 Redis 的 Key 数 |
| `failCount` | Integer | 失败条数（单条失败不中断整轮） |
| `mismatchCount` | Integer | 预热前已存在且与 DB 不一致、被覆盖的 Key 数 |
| `durationMs` | Long | 耗时（毫秒） |

**语义**：以 `COUNT(course_selection WHERE status='SELECTED')` 为基准批量写入 `teaching-class:selected-count:{teachingClassId}`，TTL 24h。**重复执行幂等**。

**失败返回**：`40948 CACHE_WARMUP_FAILED`（整轮失败时）；`40406 选课批次不存在`。

## 35.2 新增培养方案

```http
POST /api/v1/admin/training-plans
```

**提交参数**

```json
{
  "planName": "软件工程2026级培养方案",
  "majorId": 1,
  "gradeId": 1,
  "totalCredit": 160.0,
  "requiredCredit": 120.0,
  "majorElectiveCredit": 25.0,
  "publicElectiveCredit": 15.0,
  "status": 1,
  "remark": ""
}
```

**校验规则**

1. `planName` 非空，长度 ≤ 100；
2. `majorId` / `gradeId` 必须存在，否则 `40929 专业不存在` / `40930 年级不存在`；
3. **专业 + 年级组合唯一**，冲突返回 `40937 该专业年级已存在培养方案`；
4. `totalCredit > 0`，且 `requiredCredit + majorElectiveCredit + publicElectiveCredit <= totalCredit`，否则 `40938 培养方案学分配置不合法`。

**返回 JSON**：`data` 为培养方案 ID（`Long`）。

## 35.3 查询培养方案详情

```http
GET /api/v1/admin/training-plans/{planId}
```

**返回 JSON**：`data` 为 35.1 中的单个记录对象。**失败返回**：`40936 培养方案不存在`。

## 35.4 修改培养方案

```http
PUT /api/v1/admin/training-plans/{planId}
```

入参同 35.2（`planId` 由路径参数回填）。校验规则同 35.2，唯一性校验排除自身。

## 35.5 启停培养方案

```http
PATCH /api/v1/admin/training-plans/{planId}/status
```

**提交参数**：`{ "status": 0 }`；停用后该方案不参与学生学分进度计算。

# 36. 学生端学分进度与毕业风险（V2.0）

## 36.1 学生学分进度

```http
GET /api/v1/student/credit-progress
```

**角色**：STUDENT（`StudentCreditProgressController`）。学生身份从 `UserContextHolder.getStudentId()` 取。

**提交参数（Query String）**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `semesterId` | Long | 否 | 统计**截止**学期，缺省取当前学期；**该参数不参与学分累计过滤**（详见下方 C8 说明） |

> ⚠️ **C8 口径（必须遵守）**：`completedCredit` 为**跨学期累计**结果（该学生全部学期的已发布成绩），
> 与 V1.1 `GET /student/credits` 的 `completedCredit`（**仅本学期**）**不是同一个数、不可混用**。
> 实现上禁止复用 `CreditServiceImpl` / `ScoreMapper#listPublishedScoreByStudent` / `buildCourseMapOfSelection`。

**返回 JSON**

```json
    "hasPlan": true,
    "message": "",
    "completedCredit": 92.5,
    "passedCredit": 86.0,
    "planTotalCredit": 160.0,
    "progressRate": 57.8,
    "items": [
      {
        "courseType": "REQUIRED",
        "courseTypeName": "必修",
        "completedCredit": 70.0,
        "passedCredit": 66.0,
        "requiredCredit": 120.0,
        "gapCredit": 50.0,
        "progressRate": 58.3
      },
      {
        "courseType": "MAJOR_ELECTIVE",
        "courseTypeName": "专业选修",
        "completedCredit": 15.0,
        "passedCredit": 15.0,
        "requiredCredit": 25.0,
        "gapCredit": 10.0,
        "progressRate": 60.0
      },
      {
        "courseType": "PUBLIC_ELECTIVE",
        "courseTypeName": "公共选修",
        "completedCredit": 7.5,
        "passedCredit": 5.0,
        "requiredCredit": 15.0,
        "gapCredit": 7.5,
        "progressRate": 50.0
      }
    ]
  }
}
```

| 字段 | 口径 |
|---|---|
| `hasPlan` | 是否存在「专业 + 入学年级」对应的启用中培养方案 |
| `message` | `hasPlan=false` 时返回提示文案「未配置本专业本年级培养方案，暂无法计算学分进度」，**不报错** |
| `completedCredit` | **跨学期累计**：Σ `course.credit`，条件 `score.status='PUBLISHED'`（**决策 1：发布即计入，不判及格**，与 V1.1 行为一致）。**禁止复用 V1.1 的 `GET /student/credits`（后者 = 本学期口径，见 C8）** |
| `passedCredit` | **附加字段（及格学分）**：同一批累计记录中 `score_value >= passScore`（默认 60，可配）的部分。❗**仅作信息展示，不参与 `progressRate` 与任何风险计算**；与 `completedCredit` 的差异 = 已发布但不及格的课程学分 |
| `progressRate` | `completedCredit / planTotalCredit × 100`，保留 1 位小数；分母为 0 时返回 0 |
| `gapCredit` | `requiredCredit - completedCredit`，下限 0 |

> **重修不去重**：同一课程多次通过会重复计入 `completedCredit` / `passedCredit`（与 V1.1 行为一致，配置项 `credit.dedup-by-course=false`，见架构文档 C9）。

## 36.2 毕业风险预测

```http
GET /api/v1/student/graduation-risk
```

**角色**：STUDENT（`StudentGraduationRiskController`）

**返回 JSON**

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "semesterId": 1,
    "hasPlan": true,
    "message": "",
    "riskLevel": "LOW",
    "riskReason": "按当前进度，剩余学期需每学期修满 16.9 学分，达到学期上限的 56%",
    "completedCredit": 92.5,
    "passedCredit": 86.0,
    "planTotalCredit": 160.0,
    "remainingCredit": 67.5,
    "remainingSemesters": 4,
    "requiredCreditPerSemester": 16.9,
    "maxCreditPerSemester": 30.0,
    "requiredRate": 0.56,
    "gaps": [
      { "courseType": "REQUIRED", "courseTypeName": "必修", "gapCredit": 50.0 }
    ]
  }
}
```

**风险等级规则**（阈值可配，见 `smart-university.statistics.graduation-risk`）：

| 等级 | 判定 |
|---|---|
| `HIGH` | `requiredRate > high-rate`（默认 0.8） |
| `MEDIUM` | `requiredRate > medium-rate`（默认 0.6） |
| `LOW` | 其余 |

`requiredRate = requiredCreditPerSemester / maxCreditPerSemester`；`remainingSemesters = 学制（默认 4）× 2 − 已读学期数 + 1`（已读学期数按 `semester.start_date` 在「入学学期 ~ 统计截止学期」之间实算，不再用年差），最小为 1。

无培养方案时：`hasPlan=false`，`riskLevel` 返回 `LOW` 并在 `message` 中说明无法评估。

> ⚠️ **C8 口径**：`completedCredit` 与 36.1 同源、同口径（**跨学期累计 + 发布即计入**），
> **本接口不得另算一套**；与 V1.1 `GET /student/credits`（本学期口径）不可混用。
> `passedCredit` 为附加的及格学分字段，不参与风险等级计算。

# 37. 教务统计接口（V2.0）

> Controller：`AdminStatisticsController`；权限：`@RequireRole(RoleEnum.ADMIN)`

## 37.1 教室利用率统计

```http
GET /api/v1/admin/statistics/classroom-usage
```

**提交参数（Query String）**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `semesterId` | Long | 否 | 缺省当前学期 |
| `buildingName` | String | 否 | 按教学楼筛选 |
| `dimension` | String | 否 | `CLASSROOM`（默认）/ `BUILDING` / `WEEKDAY_SECTION` / `FREE_SLOT` |
| `page` / `pageSize` | Integer | 否 | 分页，缺省 1 / 10 |

**返回 JSON（`dimension=CLASSROOM`）**

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "records": [
      {
        "classroomId": 1,
        "buildingName": "致知楼",
        "roomNo": "A101",
        "capacity": 120,
        "usageCount": 6,
        "usageHours": 96,
        "totalHours": 1000,
        "usageRate": 9.6
      }
    ],
    "page": 1,
    "pageSize": 10,
    "total": 42,
    "extra": {
      "semesterId": 1,
      "daysPerWeek": 5,
      "sectionsPerDay": 10,
      "semesterWeeks": 20,
      "classroomCount": 42,
      "overallUsageRate": 12.4,
      "snapshotTime": "2026-03-10 02:00:00"
    }
  }
}
```

**口径说明**

- `usageHours = Σ((end_section − start_section + 1) × (end_week − start_week + 1))`
- `totalHours = daysPerWeek × sectionsPerDay × semesterWeeks`；**`semesterWeeks = LEAST(CEIL(DATEDIFF(semester.end_date, semester.start_date)/7), maxWeeks)`**
  —— **决策 3 / Q19 已拍板：不补 `semester.weeks` 字段，永久走推导式；`maxWeeks` 可配，默认 20**
  （参数名 `smart-university.statistics.classroom-usage.max-weeks-per-semester`）
- `usageRate = usageHours / totalHours × 100`，保留 1 位小数，**上限 100**
- **决策 5 / Q7 已拍板固化**：`daysPerWeek=5` / `sectionsPerDay=10` / `maxWeeks=20` 三项**均可配**，
  且**必须**在 `extra` 中回显（`daysPerWeek` / `sectionsPerDay` / `semesterWeeks` / `classroomCount`），便于演示时解释分母口径
- `dimension=FREE_SLOT` 时 `records` 为 `{ classroomId, buildingName, roomNo, weekday, section }` 的空闲时段列表
