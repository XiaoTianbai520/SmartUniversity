# 1. 产品目标

| 版本 | 一句话目标 |
|---|---|
| **V1.2 高并发优化版** | 让选课高峰期的每一次点击都能在毫秒级得到**确定的、正确的**结果——不超卖、不重复选课、不因为流量打垮系统。 |
| **V2.0 智慧教务版** | 把系统从「记录教务业务的台账」升级为「会自己跑的教务分析平台」——统计不用人算、状态不用人守、风险提前预警、资源有据可依。 |

三条不可妥协的底线：

1. **对外接口零破坏**：V1.2 只换内部实现，§1~§25 的 92 个接口路径与响应结构保持不变（与 `docs/接口文档.md` §32「V1.2 原则上不需要大幅修改前端接口」一致）。
2. **统计口径唯一权威源**：引入 Redis 后，「已选人数」必须只有一个权威定义（见 §7.1），不允许统计读一套数、选课读另一套数。
3. **不越界**：业务范围严格限制在选课 / 排课 / 成绩 / 学分 / 教室 / 教师 / 批次之内，`§19` 明确排除的内容一律不纳入 P0。

# 2. 版本边界与并行策略

## 2.1 边界总览

```text
                    V1.2 高并发优化版                      V2.0 智慧教务版
              ┌──────────────────────────┐         ┌──────────────────────────┐
              │  改「选课核心链路」内部   │         │  新增「分析 + 自动化」层  │
              │  · 名额计数缓存          │         │  · 培养方案 / 学分进度    │
              │  · Lua 原子扣减          │         │  · 教室利用率             │
              │  · 一致性兜底 / 降级     │         │  · 教师工作量             │
              │  · 压测                  │         │  · 课程选课分析           │
              │                          │         │  · 数据看板               │
              │  写路径（CPU/IO 密集）    │         │  · 定时任务 / 快照 / 预警 │
              └──────────────────────────┘         │  · 智能计算（待确认）     │
                                                   └──────────────────────────┘
                          ↘ 共同依赖：T0 基础契约层（Redis Key / 错误码 / 任务基础设施）↙
```

- **V1.2 只做「写链路加速 + 正确性兜底」**，不新增面向用户的业务功能。
- **V2.0 只做「读链路分析 + 自动化」**，不改动选课核心写入逻辑（候补兜底扫描除外，且只能通过 `WaitlistService` 公开方法调用）。
- 两者**文件归属互不重叠**，可真正并行。

## 2.2 依赖与冲突点（关键）

| # | 冲突点 | 说明 | 决议 / 缓解 |
|---|---|---|---|
| C1 | **「已选人数」多口径** | V1.2 引入 Redis 计数后，已选人数有三个来源：`course_selection` 的 DB count、Redis 计数 Key、`teaching_class.capacity`（容量）。V2.0 的「满班率 / 选课排行」直接使用该口径 | **权威口径唯一：DB `COUNT(course_selection WHERE status='SELECTED')`**。Redis 计数只是并发预扣减的**加速层**，不作为统计数据源。V2.0 一律走 DB 或只读快照表，**禁止读 Redis 计数 Key**。见 §7.1 |
| C2 | **V1.2 改造 `CourseSelectionServiceImpl`，V2.0 候补兜底扫描也想改** | 该文件是 V1.2 的主战场，两个版本同时改必然冲突 | **V1.2 独占 `CourseSelectionServiceImpl`**。V2.0 的候补兜底扫描只能依赖 `WaitlistService` 的公开方法（`promoteFirstWaitlist` 之类），**不得**修改该文件。若确需新能力，由 V1.2 负责人代做并登记到接口清单 |
| C3 | **V2.0 快照预计算与 V1.2 压测争抢 DB** | 快照任务全表聚合，可能与压测同时进行，导致压测数据失真 | 快照任务配置**错峰执行时段**（默认凌晨）与**单次扫描上限**；压测窗口内可通过开关暂停快照任务 |
| C4 | **多实例下定时任务重复执行** | 项目为单体应用，无调度框架，`@Scheduled` 在多实例部署时每个实例都会跑一遍 | 见待确认 **Q2**。倾向方案：任务执行前用 Redis 分布式锁（`SET key value NX PX`）抢占，抢不到直接跳过；同时在任务日志中记录实例标识 |
| C5 | **公共文件争夺** | 两个版本都要动 `RedisCommonConstant` / `RedisKeyUtil` / `ResultCodeEnum` / `application.yml` | 由 **T0 基础契约层**先行统一交付，一次性分配 Key 前缀段与错误码段；并行阶段其他任务**禁止**再改这四个文件（对齐 `V1.1_开发计划.md` §4 的做法） |
| C6 | **V2.0 成绩发布自动统计与 V1.1 通知监听器重叠** | V1.1 已在成绩发布处挂了 `NoticeEvent`；V2.0 想再挂统计 | 复用现有事件模型风格，**新增独立的统计事件/监听**，不改 `NoticeEvent` 语义。具体触发方式见 §5 |
| C7 | **统计是否需要新表** | 18 张表现有表能否支撑五项统计 + 快照 | 需要新增：培养方案表 1 张 + 统计快照表若干。见 §6.3 |
| **C8** | **学分累计口径缺失（架构评审新增，最严重）** | V1.1 `CreditServiceImpl#getCreditSummary` 的 `completedCredit` 是**限定本学期的**（`ScoreMapper#listPublishedScoreByStudent` 内部 `JOIN teaching_class tc ... WHERE tc.semester_id = :semesterId`；`buildCourseMapOfSelection` 的入参同样带学期过滤）且**不判及格**。而 S-02 学分进度 / I-01 毕业风险必须基于**跨学期累计**学分。直接复用会得出完全错误的毕业进度 | **S-02 / I-01 必须独立实现跨学期累计查询，禁止复用 V1.1 的 `GET /student/credits` 及其内部方法**（`CreditServiceImpl` / `ScoreMapper#listPublishedScoreByStudent` / `buildCourseMapOfSelection` / 任何带 `semester_id` 过滤的学分方法）。同时保留 V1.1 接口不变（对外零破坏）。两个口径数值必然不等，须在接口文档明示。**实现方案（架构文档 §7 / §11.7）**：新增 `ScoreMapper#listPublishedScoreByStudentId` + `CourseSelectionMapper#listSelectionByStudentId`（**均无学期过滤，已入 T0 冻结的 Mapper 契约清单**），计入条件 = `score.status='PUBLISHED'`（**决策 1：发布即计入**）；另输出附加字段 `passedCredit`（及格学分）。见 §7.1 |

## 4.2 V2.0 自动化能力（9 条，P0 3 条）

| ID | 需求名 | 版本 | 优先级 | 类型 | 角色 / 接口形态 | 简要描述与验收标准 | 依赖 |

# 5. V2.0 自动化能力清单

## 5.1 触发方式说明

| 触发方式 | 适用场景 | 本项目的落地形态 |
|---|---|---|
| **定时触发（Scheduled）** | 有明确周期、允许分钟级延迟的批处理：快照预计算、对账、巡检、预警 | Spring `@Scheduled`（项目已 `@EnableScheduling`，`SelectionBatchNoticeTask` 已有先例） |
| **事件驱动（Event）** | 业务动作发生后需要立即联动，且允许与主流程同事务边界：成绩发布后统计、候补递补后通知 | Spring `ApplicationEvent` + `@TransactionalEventListener`（V1.1 `NoticeEvent` 已有先例） |
| **懒加载预热（Lazy Load）** | 首次访问才需要的重聚合结果，且不强制实时：看板缓存、统计快照 | 缓存为空时同步计算并回写；与定时任务互为兜底 |

> **注意**：项目当前**没有任何 MQ**（最近两次提交已移除 RocketMQ）。因此所有"异步"能力只能落在「定时任务 + 事件监听」两种形态上。是否需要重新引入 MQ 见待确认 **Q3**。

## 5.3 通用失败兜底要求（适用于全部定时任务）

1. **异常不逃逸**：任务方法体整体 `try-catch`，任何异常都不得冒泡到调度线程池。
2. **单行不拖垮整轮**：循环体内逐条 `try-catch`，单条数据失败记录日志后继续。
3. **执行留痕**：每轮写入任务执行日志（任务编码、开始/结束时间、耗时、扫描条数、成功条数、失败条数、异常摘要、执行实例标识）。
4. **可手动触发**：每个任务提供教务端手动执行入口，便于演示与救急。
5. **互斥执行**：任务启动前抢占 Redis 分布式锁，未抢到直接跳过本轮（见待确认 **Q2**）。
6. **可关闭**：每个任务有独立开关，压测 / 演示场景可单独停用。

# 7. 数据看板指标定义（字段级口径）

> **目标**：每个指标口径明确到字段，避免后续实现歧义。
> 字段命名沿用项目现有驼峰风格（对齐 `docs/接口文档.md` §25.1 的 `averageScore` / `passRate` 等命名）。

## 7.1 全局基础口径（C1 决议）

| 口径项 | 定义 | 说明 |
|---|---|---|
| **已选人数（权威）** | `COUNT(course_selection.id) WHERE teaching_class_id = :id AND status = 'SELECTED'` | **唯一权威源**。所有统计、排行、满班率一律使用此口径 |
| **学分维度（关键）** | V2.0 的学分进度一律为**跨学期累计**，V1.1 的 `completedCredit` 为**本学期且不判及格** | 见下方「学分口径」三行。**两者数值必然不相等，属预期差异，须在接口文档中明示** |
| **候补人数** | `COUNT(course_selection.id) WHERE teaching_class_id = :id AND status = 'WAITING'` | 与已选人数互斥，不重复计算 |
| **退课数** | `COUNT(course_selection.id) WHERE teaching_class_id = :id AND status = 'WITHDRAWN'` | 只统计最终处于退课状态的记录 |
| **Redis 计数** | 仅供选课并发预扣减使用 | **严禁**作为任何统计数据源 |
| **当前学期** | `semester.status = 'ACTIVE'` | 沿用 V1.0 `SemesterService#getCurrentSemester` |
| **当前批次** | 当前学期下 `selection_batch` 的有效批次 | 沿用 V1.0 批次判定逻辑 |
| **及格线** | `score_value >= 60` | 对齐 §25.1 `passRate` 口径 |
| **优秀线** | `score_value >= 85` | 对齐 §25.1 `excellentRate` 口径 |
| **本学期已修得学分**（V1.1 既有） | Σ `course.credit` WHERE 对应 `score.status = 'PUBLISHED'` **且不判及格、且限定本学期**（`teaching_class.semester_id = :semesterId`） | **以 V1.1 代码实际行为为准**（`CreditServiceImpl#getCreditSummary`），与 §6.7 文档的简略描述存在差异。V2.0 **不得**用该口径做毕业进度计算；**该口径永久保留、不改**（决策 1） |
| **累计已修得学分**（V2.0 专用） | Σ `course.credit` WHERE 对应 `score.status = 'PUBLISHED'` **且不限学期**（跨全部学期累计、不判及格） | S-02 / I-01 的唯一口径。**必须独立实现，不可复用 V1.1 的 `GET /student/credits`**（C8）。实现依赖新增的 `ScoreMapper#listPublishedScoreByStudentId` + `CourseSelectionMapper#listSelectionByStudentId`（均无学期过滤，已入架构文档 §11.7 T0 冻结清单） |
| **累计及格学分**（V2.0 附加字段，Q10 已拍板输出） | Σ `course.credit` WHERE `score.status = 'PUBLISHED'` 且 `score_value >= 60`，跨学期累计 | **字段名为 `passedCredit`**，作为**附加字段**输出；**不参与** `progressRate` / 风险等级计算。与 `completedCredit` 的差值 = 已发布但不及格的课程学分。注意：同一课程重修多次通过会重复计入（架构文档 C9，默认不去重） |

## 7.2 看板指标明细

| 指标 key | 中文名 | 计算口径（字段级） | 单位 / 精度 |
|---|---|---|---|
| `studentCount` | 本学期在读学生数 | `COUNT(student.id) WHERE student.status = 1`（在册总数，`student` 表无学期维度，无法按学期过滤） | 人，整数 |
| `selectedStudentCount` | 本学期已选课学生数 | `COUNT(DISTINCT course_selection.student_id) WHERE course_selection.batch_id = :currentBatchId AND status = 'SELECTED'` | 人，整数 |
| `courseCount` | 本学期开设课程数 | `COUNT(DISTINCT teaching_class.course_id) WHERE teaching_class.semester_id = :semesterId AND teaching_class.status IN ('AVAILABLE','CLOSED')` | 门，整数 |
| `teachingClassCount` | 本学期教学班数 | `COUNT(teaching_class.id) WHERE teaching_class.semester_id = :semesterId AND teaching_class.status <> 'CANCELLED'` | 个，整数 |
| `teacherCount` | 本学期任课教师数 | `COUNT(DISTINCT teaching_class.teacher_id) WHERE teaching_class.semester_id = :semesterId AND teaching_class.status <> 'CANCELLED'` | 人，整数 |
| `selectionCount` | 当前选课人次 | `COUNT(course_selection.id) WHERE course_selection.batch_id = :currentBatchId AND course_selection.status = 'SELECTED'` | 人次，整数 |
| `waitlistCount` | 当前候补人次 | `COUNT(course_selection.id) WHERE course_selection.batch_id = :currentBatchId AND course_selection.status = 'WAITING'` | 人次，整数 |
| `withdrawCount` | 本学期退课人次 | `COUNT(course_selection.id) WHERE course_selection.batch_id = :currentBatchId AND course_selection.status = 'WITHDRAWN'` | 人次，整数 |
| `fullClassRate` | 课程满班率 | `fullClassCount / selectionClassCount × 100`；`fullClassCount` = 批次内 `已选人数 >= teaching_class.capacity` 的教学班数；`selectionClassCount` = 当前批次 `selection_batch_class` 关联且 `teaching_class.status <> 'CANCELLED'` 的教学班数 | 百分比，保留 1 位小数；分母为 0 时返回 0 |
| `classroomUsageRate` | 教室利用率 | `usedSectionCount / totalSectionCount × 100`；`usedSectionCount` = 本学期 `teaching_class_schedule` 的 `Σ((end_section − start_section + 1) × (end_week − start_week + 1))`；`totalSectionCount` = `教室可用数 × 每周可排节次 × 学期周数`；**`semester` 表无周数字段**，学期周数按 `LEAST(CEIL(DATEDIFF(end_date, start_date)/7), 上限)` 推导，上限默认 20 且可配（见 Q7、Q19） | 百分比，保留 1 位小数；上限 100 |
| `avgTeacherWorkload` | 教师平均工作量 | `totalHours / teacherCount`；`totalHours` = 本学期各班 `Σ((end_section − start_section + 1) × (end_week − start_week + 1))` | 课时，保留 1 位小数 |
| `avgCreditProgressRate` | 平均学分完成度 | `AVG(stat_credit_progress.progress_rate)`，仅统计有培养方案的学生 | 百分比，保留 1 位小数 |
| `unpublishedClassCount` | 待发布成绩教学班数 | 本学期存在 `course_selection.status='SELECTED'` 且无 `score` 记录或 `score.status='UNPUBLISHED'` 的教学班去重计数 | 个，整数 |
| `batchStatus` | 当前选课批次状态 | `selection_batch.status`（`NOT_STARTED` / `IN_PROGRESS` / `ENDED`），无批次时返回 `NOT_STARTED` | 枚举 |
| `snapshotTime` | 数据快照时间 | 看板数据的生成时间；命中快照时为 `stat_snapshot.generated_at`，实时计算时为当前时间 | datetime |
