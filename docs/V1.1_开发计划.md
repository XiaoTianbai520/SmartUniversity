# 高校智慧教务选课平台 V1.1 开发计划

## 1. 版本定位

V1.1 为**业务增强版**，目标是在 V1.0 完整业务闭环之上补齐真实教务系统的辅助能力，达到"可独立演示、可测试、可验收"的状态。

V1.1 四条主线：

```text
T2 候补选课   T3 系统通知   T4 批量导入导出   T5 教师成绩统计
```

V1.1 **不**处理的内容（属于后续版本）：

- Redis + Lua 高并发选课、压力测试（V1.2）；
- 培养方案、学分进度分析、教室利用率、数据看板（V2.0）；
- 学费缴纳、宿舍、图书馆等校园综合服务（暂不建议开发）。

# 3. 通用开发约定

## 3.1 代码规约

严格遵循项目既有的《代码命名与开发规范》：

- 方法前缀：`get` / `list` / `count` / `save` / `update` / `remove`；
- 单对象请求参数统一命名 `requestParam`；
- 返回值变量用 `result`，循环变量用 `each`，Map 遍历用 `entry`，异常变量用 `ex`；
- DO 后缀 `xxxDO`，DTO 分 `xxxReqDTO` / `xxxRespDTO`；
- 类注释说明意图即可，方法注释说明意图与 `@param` / `@return`；
- 优先复用 HuTool 工具类，禁止重复造轮子。

## 3.2 分层约定

沿用 V1.0 结构：

```text
controller → service / service.impl → mapper → domain.entity
```

- Controller 只做参数透传与结果包装，不写业务逻辑；
- 单表操作由 MyBatis-Plus `BaseMapper` 承担，Mapper 中以 `default` 方法按业务语义命名；
- 复杂跨表统计才落到 XML。

## 3.3 事务与异常

- 业务异常统一抛 `BizException(ResultCodeEnum.XXX)` 或 `BizException(ResultCodeEnum.XXX, "补充说明")`，由 `GlobalExceptionHandler` 兜底；
- 写操作加 `@Transactional(rollbackFor = Exception.class)`；
- Excel 逐行导入场景**不得**包裹外层大事务，必须逐行隔离处理。

## 3.4 权限控制

- 所有新接口按角色分组到对应 Controller，并用 `@RequireRole(RoleEnum.XXX)` 标注；
- 学生端接口一律从 `UserContextHolder` 取当前身份，**禁止**信任请求参数中的学生 / 教师 ID；
- 教师端教学班接口必须校验 `teaching_class.teacher_id` 归属。

## 3.5 编译验证

每个任务完成后，在项目根目录执行：

```bash
mvn -o -B compile -DskipTests
```

离线模式即可完成编译。若本地仓库缺依赖，改用：

```bash
mvn -B compile -DskipTests -Dhttp.proxyHost=127.0.0.1 -Dhttp.proxyPort=7890 -Dhttps.proxyHost=127.0.0.1 -Dhttps.proxyPort=7890
```

**注意**：并行阶段单个任务可能因为依赖其他模块尚未落地的类而编译失败。此时只需保证本任务自身新增文件的语法正确，跨模块编译问题统一由 T6 收尾。

## 5.2 事件模型

```java
public class NoticeEvent {
    private NoticeTypeEnum noticeType;   // 通知类型
    private String title;                // 标题
    private String content;              // 内容
    private List<Long> receiverUserIds;  // 接收人 sys_user.id 列表（已解析）
    private RoleEnum receiverRole;       // 接收角色快照
    private Long bizId;                  // 业务 ID，用于去重与跳转
}
```

发布方式：

```java
noticeEventPublisher.publish(NoticeEvent.builder()
        .noticeType(NoticeTypeEnum.SCORE_PUBLISHED)
        .title("成绩已发布")
        .content("..." )
        .receiverUserIds(userIds)
        .receiverRole(RoleEnum.STUDENT)
        .bizId(teachingClassId)
        .build());
```

## 5.3 接收人解析

```java
public interface NoticeTargetResolver {
    List<Long> listUserIdsByRole(RoleEnum role);
    List<Long> listUserIdsByTeachingClassId(Long teachingClassId);

```

实现方式要求：**只使用 MyBatis-Plus `BaseMapper` 自带的 `selectList` 等方法**，不修改 `StudentMapper` / `CourseSelectionMapper`，避免与 T2、T4 争抢文件。

## 5.4 Redis Key


# 7. 验收标准

## 7.1 候补选课

- 名额未满时不能加入候补，返回明确提示；
- 名额满时可以加入候补，候补序号在班级内递增且不重复；
- 候补列表返回正确位次，取消候补后其他人的位次自动前移（实时计算）；
- 退课后自动递补候补队列第一位，且递补前重新执行全部选课校验；
- 递补失败（如该生已超学分上限）时该条候补失效，并继续尝试下一位；
- 递补后教学班正式人数正确，Redis 计数与数据库一致；
- 候补成功后本人收到通知。

## 7.2 系统通知

- 五类通知均能落库；
- 事件重复触发不产生重复通知；
- 学生只能看到自己的通知；
- 未读数与实际未读条数一致，标记已读后未读数正确下降。

## 7.3 批量导入导出

- 模板可下载，模板列与解析列完全一致；
- 导入非 xlsx 文件返回明确错误；
- 单行数据非法时不影响其他行，失败明细带行号与原因；
- 导入学生后可直接用账号登录；
- 导出的 xlsx 可被正常打开，数据与查询条件一致；
- 教师只能导出 / 导入自己教学班的数据。

## 7.4 教师成绩统计

- 无成绩时不报错，人数为 0，各项比率为 0；
- 平均分、最高分、最低分、及格率、优秀率计算正确；
- 五段分布人数之和等于已录入成绩人数；
- 教师只能统计自己的教学班。

## 7.5 工程整体

- `mvn -o -B compile -DskipTests` 通过；
- V1.0 全部接口行为保持不变；
- 无跨任务的重复类名、无循环依赖。
