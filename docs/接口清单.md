## 1. 文档说明

本文档用于定义《高校智慧教务选课平台》前后端交互接口，覆盖 V1.0 基础接口与 V1.1 业务增强接口，是全项目唯一的接口契约文档。

接口设计基于以下前提：

- 后端：Spring Boot
- 协议：HTTP / HTTPS
- 数据格式：JSON
- 接口风格：RESTful
- 认证方式：Bearer Token
- 接口版本：V1
- 基础路径：`/api/v1`

角色：

```text
STUDENT  学生
TEACHER  教师
ADMIN    教学管理员
```

# 2. 通用约定

## 2.1 请求头

除登录接口外，其他需要登录的接口统一携带：

```http
Authorization: Bearer <token>
Content-Type: application/json
```

---

## 2.2 统一响应结构

成功：

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

失败：

```json
{
  "code": 40001,
  "message": "参数错误",
  "data": null
}
```

分页：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "records": [],
    "page": 1,
    "pageSize": 20,
    "total": 100
  }
}
```

---

## 2.3 其他通用约定

| 项 | 说明 |
|---|---|
| 鉴权失败 | 未登录或 Token 失效返回 `40101` / `40102` |
| 越权访问 | 角色不匹配返回 `40301`（由 `@RequireRole` 控制） |
| 参数校验 | 请求体统一走 `@Valid`，校验失败返回 `40001` |
| 分页入参 | `page`（默认 1）、`pageSize`（默认 20） |
| 分页出参 | `PageResult<T>`：`{ records, page, pageSize, total }` |
| 时间格式 | `yyyy-MM-dd HH:mm:ss` |
| 空值策略 | 值为 `null` 的字段不参与序列化 |

### 权限

### 请求体

```json

  "username": "20260001",
  "password": "123456",
  "loginType": "STUDENT"
}
```

`loginType`：

```text

TEACHER
ADMIN
```

### 返回

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "token": "xxxxx",
    "userId": 1,
    "role": "STUDENT",
```

# 6.1 查询可选课程

```http
GET /api/v1/student/teaching-classes
```

### 权限

```text
STUDENT
```

### 查询参数

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `keyword` | String | 否 | 课程名称 / 教师名称 |
| `courseType` | String | 否 | 课程性质 |
| `weekday` | Integer | 否 | 星期 1-7 |
| `page` | Integer | 否 | 默认 1 |
| `pageSize` | Integer | 否 | 默认 20 |

示例：

```http
GET /api/v1/student/teaching-classes?keyword=Java&weekday=1&page=1&pageSize=20
```

### 返回

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "records": [
      {
        "teachingClassId": 100,
        "classCode": "2026-JAVA-01",
        "className": "Java程序设计01班",
        "courseId": 10,
        "courseCode": "SE202",
        "courseName": "Java程序设计",
        "courseType": "REQUIRED",
        "credit": 3.0,
        "teacherId": 20,
        "teacherName": "张老师",
        "capacity": 60,
        "selectedCount": 42,
        "remainingCount": 18,
        "schedules": [
          {
            "weekday": 1,
            "startSection": 1,
            "endSection": 2,
            "startWeek": 1,
            "endWeek": 16,
            "buildingName": "第一教学楼",
            "roomNo": "A101"
          }
        ]
      }
    ],
    "page": 1,
    "pageSize": 20,
    "total": 1
  }
}
```

### 核心业务规则

该接口不能查询全部教学班后直接返回。

必须根据当前登录学生自动过滤：

```text
当前学生专业
+
当前学生年级
+
当前学期
+
当前有效选课批次
+
教学班开放状态
```

只有符合全部选课条件的教学班才能返回。

搜索条件只允许在：

```text
学生已经有权限查看的教学班集合
```

中继续筛选。

# 6.3 学生选课

```http
POST /api/v1/student/selections
```

### 权限

```text
STUDENT
```

### 请求体

```json
{
  "teachingClassId": 100
}
```

前端不需要传：

```text
studentId
batchId
```

这些信息应该由后端根据当前登录用户和当前选课批次获取。

### 成功返回

```json
{
  "code": 200,
  "message": "选课成功",
  "data": {
    "selectionId": 5001,
    "teachingClassId": 100,
    "status": "SELECTED",
    "selectedAt": "2026-09-11 20:30:00"
  }
}
```

### 后端校验顺序

建议：

```text
1. 当前用户是否为学生
2. 教学班是否存在
3. 教学班是否属于当前学期
4. 当前是否存在有效选课批次
5. 教学班是否属于当前选课批次
6. 教学班状态是否允许选课
7. 专业是否符合
8. 年级是否符合
9. 是否已经选择
10. 是否与已选课程时间冲突
11. 当前学分 + 目标课程学分是否超过学期上限
12. 教学班容量是否已满
13. 创建/恢复选课记录
```

### 可能错误

```text
40908 学生课程时间冲突
40909 重复选课
40910 课程容量已满
40911 超过最大学分限制
40912 当前不在选课时间
40914 专业不符合选课条件
40915 年级不符合选课条件
```


必须校验：

```text

+
```

# 21. 关键接口安全规则

## 21.1 不允许客户端传当前用户身份

以下接口中：

```text
studentId
teacherId
userId
```

如果代表“当前登录用户”，则禁止由前端传递。

例如学生选课不能设计为：

```json
{
  "studentId": 1001,
  "teachingClassId": 100
}
```

正确设计：

```json
{
  "teachingClassId": 100
}
```

后端从 Token 中获取当前学生。

---

## 21.2 教师接口必须做数据权限校验

即使教师拥有：

```text
TEACHER
```

角色，也不能操作其他教师教学班。

因此：

```text
角色权限
```

只能解决：

> 你是不是教师。

还需要数据权限解决：

> 这个教学班是不是你的。

---

## 21.3 学生课程查询和选课必须双重校验

第一层：

```text
查询列表时过滤
```

第二层：

```text
点击选课后后端重新校验
```

不能因为前端已经隐藏无权限课程，就省略后端权限判断。

## 24.9 导入成绩

```http
POST /api/v1/teacher/teaching-classes/{teachingClassId}/scores/import
Content-Type: multipart/form-data
```

权限：`ROLE_TEACHER`

模板列：学号、姓名、成绩

行校验规则：

| 规则 | 错误提示 |
|---|---|
| 学号不在本教学班或未处于已选状态 | 学生不属于该教学班 |
| 成绩为空或非数字 | 成绩格式错误 |
| 成绩不在 0 ~ 100 | `40932` |
| 成绩已发布 | `40916` |

响应格式同 24.1。

# 25. 教师成绩统计接口

## 25.1 查询教学班成绩统计

```http
GET /api/v1/teacher/teaching-classes/{teachingClassId}/score-statistics
```

权限：`ROLE_TEACHER`

路径参数：`teachingClassId` 教学班 ID

响应：

```json
{
  "teachingClassId": 88,
  "teachingClassName": "2026秋季 Java程序设计 01班",
  "courseName": "Java程序设计",
  "teacherName": "张老师",
  "selectedCount": 60,
  "scoredCount": 58,
  "unscoredCount": 2,
  "averageScore": 78.6,
  "maxScore": 99.0,
  "minScore": 42.5,
  "passRate": 89.7,
  "excellentRate": 25.9,
  "distribution": [
    { "range": "0-59",   "count": 6,  "rate": 10.3 },
    { "range": "60-69",  "count": 12, "rate": 20.7 },
    { "range": "70-79",  "count": 25, "rate": 43.1 },
    { "range": "80-89",  "count": 11, "rate": 19.0 },
    { "range": "90-100", "count": 4,  "rate": 6.9 }
  ]
}
```

字段口径：

| 字段 | 说明 |
|---|---|
| `selectedCount` | 该教学班正式选课人数 |
| `scoredCount` | 已录入成绩的人数 |
| `unscoredCount` | 未录入成绩的人数 |

# 32. 后续版本接口预留

> **说明**：本章为 V1.0 规划期的早期设想，其中「候补选课」与「站内通知」已由 V1.1 实现，
> 实际接口路径以 [§22 候补选课接口](#22-候补选课接口) 与 [§23 系统通知接口](#23-系统通知接口) 为准，
> 与此处预留的路径不同（例如候补实际为 `POST /api/v1/student/teaching-classes/{teachingClassId}/waitlist`，而非 `/student/waitlists`）。

V1.1 候补选课可以新增：

```http
POST   /api/v1/student/waitlists
GET    /api/v1/student/waitlists

```

通知：

```http
GET   /api/v1/notifications

```

V1.2 高并发版本原则上不需要大幅修改前端接口：

```http
POST /api/v1/student/selections
```

接口保持不变。

只是内部实现从：

```text
普通数据库事务
```

升级为：

```text
Redis
+
Lua
+
数据库事务
+
消息队列
```

这样可以保证前端接口稳定，后端内部持续演进。

# 33. 接口设计总结

V1 接口设计重点遵循以下原则：

1. 三类角色接口路径明确分离；
2. 当前用户身份从 Token 获取，不信任前端传入；
3. 学生只能查询自己具备选课权限的课程；
4. 查询权限和操作权限必须分别校验；
5. 教师不仅要做角色校验，还要做教学班数据归属校验；
6. 学生选课接口集中承载核心业务校验；
7. 课表和学分通过已有业务数据动态生成；
8. Entity、Request DTO、Response DTO 分离；
9. 业务冲突使用明确错误码返回；
10. V1.1、V1.2 尽量保持现有接口稳定，通过内部实现升级功能。
