## 1. 文档说明

本文档用于定义《高校智慧教务选课平台》前后端交互接口，覆盖 V1.0 基础接口与 V1.1 业务增强接口，是全项目唯一的接口契约文档。

接口设计基于以下前提：

- 后端：Spring Boot
- 协议：HTTP / HTTPS
- 数据格式：JSON
- 接口风格：RESTful
- 认证方式：Bearer Token
- 接口版本：V1
- 基础路径：`/api/v1`

角色：

```text
STUDENT  学生
TEACHER  教师
ADMIN    教学管理员
```

# 2. 通用约定

## 2.1 请求头

除登录接口外，其他需要登录的接口统一携带：

```http
Authorization: Bearer <token>
Content-Type: application/json
```

---

## 2.2 统一响应结构

所有接口（导出类接口除外，见 [§24](#24-批量导入导出接口)）均返回 `Result<T>`，固定四个字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | int | 业务状态码，成功固定为 `200` |
| `message` | String | 提示信息；未显式指定时为 `success` |
| `data` | T | 业务数据，无数据时为 `null` |
| `timestamp` | long | 服务端毫秒时间戳，便于排查问题 |

成功：

```json
{
  "code": 200,
  "message": "success",
  "data": {},
  "timestamp": 1760000000000
}
```

失败：

```json
{
  "code": 40001,
  "message": "参数错误",
  "data": null,
  "timestamp": 1760000000000
}
```

分页：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "records": [],
    "page": 1,
    "pageSize": 20,
    "total": 100
  },
  "timestamp": 1760000000000
}
```

### message 取值规律

后端 `Result.success(data)` 不带文案时，`message` 固定为 `success`；
带文案时以代码里的文案为准，例如：

| 场景 | message |
|---|---|
| 新增学生 / 教师 | 新增成功 |
| 修改学生 / 教师 | 修改成功 |
| 新增 / 修改基础数据、教学班、批次、排课 | 保存成功 |
| 改状态（学生 / 教师 / 基础数据 / 教学班 / 批次） | 状态修改成功 |
| 排课删除 | 删除成功 |
| 批次添加 / 移除教学班 | 添加成功 / 移除成功 |
| 学生选课 / 退课 | 选课成功 / 退课成功 |
| 加入 / 取消候补 | 加入候补成功 / 取消候补成功 |
| 成绩保存 / 发布 | 成绩保存成功 / 成绩发布成功 |
| 登录 / 登出 | 登录成功 / 退出成功 |

## 2.3 其他通用约定

| 项 | 说明 |
|---|---|
| 鉴权失败 | 未登录或 Token 失效返回 `40101` / `40102` |
| 越权访问 | 角色不匹配返回 `40301`（由 `@RequireRole` 控制） |
| 参数校验 | 请求体统一走 `@Valid`，校验失败返回 `40001` |
| 分页入参 | `page`（默认 1）、`pageSize`（默认 20） |
| 分页出参 | `PageResult<T>`：`{ records, page, pageSize, total }` |
| `LocalDateTime` 时间格式 | ISO-8601，形如 `2026-09-15T08:00:00`（**中间是大写 T**） |
| `LocalDate` 日期格式 | ISO-8601，形如 `2026-09-01` |
| 空值策略 | 值为 `null` 的字段不参与序列化 |

> **时间格式说明**：`application.yml` 里配的 `spring.jackson.date-format: yyyy-MM-dd HH:mm:ss`
> 只对 `java.util.Date` 生效。本项目 DO 与 RespDTO 全部使用 `java.time.LocalDateTime` / `LocalDate`，
> 且没有任何 `@JsonFormat` 或自定义序列化器，因此实际输出的是 ISO-8601（带 `T`）。
> 前端解析时间字段时请以 `T` 分隔为准，不要按 `yyyy-MM-dd HH:mm:ss` 切分字符串。
> 反过来，请求体里传 `2026-09-15 08:00:00`（空格）或 `2026-09-15T08:00:00` 都能被正常反序列化。

# 5. 登录认证接口

> 本章及后续所有接口的返回均为统一结构 `Result<T>`，含 `code` / `message` / `data` / `timestamp` 四个字段，
> 示例中的 `timestamp` 为毫秒时间戳，实际值每次不同。

## 5.1 登录

```http
POST /api/v1/auth/login
```

**权限**：无需登录。

### 提交 JSON

```json
{
  "username": "20260001",
  "password": "123456",
  "loginType": "STUDENT"
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `username` | String | 是 | 登录账号 |
| `password` | String | 是 | 明文密码 |
| `loginType` | String | 是 | `STUDENT` / `TEACHER` / `ADMIN`，必须与账号实际角色一致 |

### 返回 JSON

```json
{
  "code": 200,
  "message": "登录成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9.eyJ1c2VySWQiOjEsInJvbGUiOiJTVFVERU5UIn0.xxx",
    "userId": 1,
    "role": "STUDENT",
    "username": "20260001",
    "displayName": "张三"
  },
  "timestamp": 1760000000000
}
```

### 失败返回

```json
{
  "code": 40401,
  "message": "用户不存在",
  "data": null,
  "timestamp": 1760000000000
}
```

### 业务规则

- 账号必须存在；
- 密码必须正确；
- 账号必须为启用状态（`sys_user.status = 1`）；
- 登录入口与用户角色必须匹配，用学生账号选 `ADMIN` 登录会被拒绝。

```http

```

**权限**：`STUDENT` / `TEACHER` / `ADMIN`。

### 提交 JSON

无请求体。

```json
{}
```

# 6. 学生端接口

## 6.1 查询可选课程

```http
GET /api/v1/student/teaching-classes
```

**权限**：`STUDENT`

### 提交参数（Query String）

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `keyword` | String | 否 | 课程名称 / 课程编号 / 教师名称 |
| `courseType` | String | 否 | REQUIRED / MAJOR_ELECTIVE / PUBLIC_ELECTIVE |
| `weekday` | Integer | 否 | 星期 1-7 |
| `page` | Integer | 否 | 默认 1 |
| `pageSize` | Integer | 否 | 默认 20 |

### 请求示例

```http
GET /api/v1/student/teaching-classes?keyword=Java&weekday=1&page=1&pageSize=20
```

> 该接口无请求体。`StudentTeachingClassPageQueryReqDTO` 里虽然还有
> `studentId` / `majorId` / `gradeId` / `semesterId` / `batchId` 五个字段，
> 但它们全部由后端用 Token 中的学生信息与当前学期、当前批次**强制覆盖**，前端传了也不会生效，调用时不要传。

### 返回 JSON

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "records": [
      {
        "teachingClassId": 100,
        "classCode": "2026-JAVA-01",
        "className": "Java程序设计01班",
        "courseId": 10,
        "courseCode": "SE202",
        "courseName": "Java程序设计",
        "courseType": "REQUIRED",
        "credit": 3.0,
        "teacherId": 20,
        "teacherName": "张老师",
        "capacity": 60,
        "selectedCount": 42,
        "remainingCount": 18,
        "schedules": [
          {
            "weekday": 1,
            "startSection": 1,
            "endSection": 2,
            "startWeek": 1,
            "endWeek": 16,
            "buildingName": "第一教学楼",
            "roomNo": "A101"
          }
        ]
      }
    ],
    "page": 1,
    "pageSize": 20,
    "total": 1
  },
  "timestamp": 1760000000000
}
```

### 核心业务规则

该接口不能查询全部教学班后直接返回。必须根据当前登录学生自动过滤
（对应 `TeachingClassMapper.listStudentVisibleTeachingClass` 的 `WHERE` 条件，全部为 AND）：

```text
教学班状态 = AVAILABLE
+
教学班学期 = 当前学期
+
该学期状态 = ACTIVE
+
教学班已在当前选课批次中开放（selection_batch_class 存在记录）
+
学生的专业在该教学班的允许专业内（teaching_class_major 存在记录）
+
学生的年级在该教学班的允许年级内（teaching_class_grade 存在记录）
+
课程状态为启用（course.status = 1）
```

> 注意专业与年级用的是 `EXISTS` 子查询而非「未配置即放行」：
> 一个教学班如果没配 `teaching_class_major` 或 `teaching_class_grade`，它对所有学生都不可见。

### 失败场景

```text
40301 无接口访问权限（非学生角色）
40912 当前不在选课时间（当前学期没有进行中的批次）
```

## 6.3 学生选课

```http
POST /api/v1/student/selections
```

**权限**：`STUDENT`

### 提交 JSON

```json
{
  "teachingClassId": 100
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `teachingClassId` | Long | 是 | 目标教学班 ID |

前端不需要传 `studentId` / `batchId`，这些信息由后端根据当前登录用户和当前选课批次获取。

### 返回 JSON

```json
{
  "code": 200,
```

教学班状态取值：


## 16.1 创建教学班


| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `classCode` | String | 是 | 教学班编号，全局唯一 |
| `className` | String | 是 | 教学班名称 |
| `courseId` | Long | 是 | 所属课程 ID |
| `semesterId` | Long | 是 | 所属学期 ID |
| `teacherId` | Long | 是 | 任课教师 ID |
| `capacity` | Integer | 是 | 容量上限 |
| `majorIds` | Long[] | 是 | 允许选课的专业 ID 集合 |
| `gradeIds` | Long[] | 是 | 允许选课的年级 ID 集合 |

```json

  "message": "保存成功",
  "data": 100,
  "timestamp": 1760000000000
}
```

`data` 为教学班 ID。

### 说明

`majorIds` 和 `gradeIds` 用于建立：

```text
teaching_class_major
teaching_class_grade
```

即该教学班允许选课的专业与年级范围。

> **重要**：学生端可见范围用的是 `EXISTS` 子查询，**不是**「未配置即放行」。
> `majorIds` / `gradeIds` 只要有一个没配，该教学班就对所有学生不可见。
> 因此创建教学班时必须同时配置专业与年级，否则学生端查不到它。

### 业务规则

- 课程必须存在，否则 `40404`；
- 新增时 `classCode` 必须唯一，冲突返回 `40905`；
- 新增后状态固定为 `DRAFT`，需调用 [§16.5](#165-修改教学班状态) 切换为 `AVAILABLE` 才会对学生开放；

# 21. 关键接口安全规则

## 21.1 不允许客户端传当前用户身份

以下接口中：

```text
studentId
teacherId
userId
```

如果代表“当前登录用户”，则禁止由前端传递。

例如学生选课不能设计为：

```json
{
  "studentId": 1001,
  "teachingClassId": 100
}
```

正确设计：

```json
{
  "teachingClassId": 100
}
```

后端从 Token 中获取当前学生。

---

## 21.2 教师接口必须做数据权限校验

即使教师拥有：

```text
TEACHER
```

角色，也不能操作其他教师教学班。

因此：

```text
角色权限
```

只能解决：

> 你是不是教师。

还需要数据权限解决：

> 这个教学班是不是你的。

---

## 21.3 学生课程查询和选课必须双重校验

第一层：

```text
查询列表时过滤
```

第二层：

```text
点击选课后后端重新校验
```

不能因为前端已经隐藏无权限课程，就省略后端权限判断。

## 删除策略

本系统对"删除"统一采用**分级策略**：文档 §8 ~ §19 的基础数据管理接口**不提供实体硬删**，删除语义通过状态字段（启用 / 停用，`status` 0/1）表达。前端应理解：**停用即删除**。

### 一、分级规则

| 类型 | 覆盖实体 | 删除方式 | 说明 |
|---|---|---|---|
| 核心业务实体 | 学生、教师、课程、学期、教学班、选课批次 | **软删（停用）** | 被 `course_selection`、`score`、`teaching_class`、`teaching_class_schedule` 等历史数据外键引用，硬删会破坏数据一致性与审计链路 |
| 字典 / 配置类 | 专业、年级、行政班、教室 | 默认**软删（停用）** | 如确需彻底清理"误建且零引用"的记录，可物理删，但必须前置引用校验（见第三节） |
| 纯关联行 | 排课（`teaching_class_schedule`）、批次-教学班关联（`selection_batch_class`） | **物理删** | 无业务历史，硬删安全；现有接口 §17.4、§19.3，删除后推送通知 |
| 业务动作 | 学生退课、取消候补 | **状态流转（软删）** | 非实体删除，仅改 `course_selection.status` / 候补记录状态 |

### 二、为何核心实体不做硬删

- 学生 / 教师删除会导致其历史选课记录、成绩、教学班归属成为孤儿数据；
- 课程 / 学期 / 教学班 / 选课批次是选课与成绩的载体，删除后无法追溯"某学生某学期上了什么课、得多少分"；
- 上述实体已提供 `PATCH .../{id}/status` 停用接口，停用后账号无法登录、数据不再参与业务，等价于删除且可恢复。

### 三、字典类如需硬删的前置校验

若后续为专业 / 年级 / 行政班 / 教室增加物理删除接口，必须满足：

```text
删除前校验该记录零引用：
专业 / 年级 / 行政班 → 无任何 student 引用
教室          → 无任何 teaching_class_schedule 引用
```

存在引用时返回引用冲突错误码（禁用专业的关联校验已落地，见 [§10.5](#105-修改专业状态)；若后续增加物理删除接口，可复用 40933/40934 关联冲突语义或新增错误码）。

### 四、前端对接约定

- 列表页的"删除"按钮对应后端的"停用"操作；
- 已停用数据通过 `status` 过滤，不在正常业务流中出现；
- 切勿假定存在 `DELETE /admin/{entity}/{id}` 实体删除接口——当前未提供。

# 33. 接口设计总结

V1 接口设计重点遵循以下原则：

1. 三类角色接口路径明确分离；
2. 当前用户身份从 Token 获取，不信任前端传入；
3. 学生只能查询自己具备选课权限的课程；
4. 查询权限和操作权限必须分别校验；
5. 教师不仅要做角色校验，还要做教学班数据归属校验；
6. 学生选课接口集中承载核心业务校验；
7. 课表和学分通过已有业务数据动态生成；
8. Entity、Request DTO、Response DTO 分离；
9. 业务冲突使用明确错误码返回；
10. V1.1、V1.2 尽量保持现有接口稳定，通过内部实现升级功能。

### 风险等级规则（阈值可配 `smart-university.statistics.graduation-risk`）

| 等级 | 判定 |
|---|---|
| `HIGH` | `requiredRate > high-rate`（默认 0.8） |
| `MEDIUM` | `requiredRate > medium-rate`（默认 0.6） |
| `LOW` | 其余 |

> ⚠️ **C8 口径**：`completedCredit` 与 36.1 同源同值（跨学期累计 + 发布即计入），不得另算一套；`passedCredit` 不参与风险等级计算。无培养方案时 `riskLevel` 返回 `LOW` 并说明。

> **剩余学期数口径（V2.0 / M-01）**：`remainingSemesters = 学制（默认 4）× 2 − 已读学期数 + 1`，其中已读学期数按 `semester` 表 `start_date >= 入学学期 start_date 且 start_date <= 统计截止学期 start_date` 实算（不用「当前学年 − entry_year」的年差），结果最小为 1。示例：以 2026-2027-1 为统计学期，2026级=8、2025级=6、2024级=4、2023级=2、2022级=1。`requiredRate = requiredCreditPerSemester / maxCreditPerSemester`。

## 42.3 学期数据归档

```http
POST /api/v1/admin/semesters/{semesterId}/archive
```

**权限**：`ADMIN`

### 提交参数

| 参数 | 位置 | 必填 | 说明 |
|---|---|---|---|
| `archiveTypes` | query | 否 | 逗号分隔 `SELECTION` / `SCORE` / `OVERVIEW`，缺省全部三类 |

### 返回 JSON

```json
{
  "code": 200, "message": "归档完成",
  "data": { "semesterId": 1, "archiveTypes": ["SELECTION", "SCORE", "OVERVIEW"], "successCount": 3, "failCount": 0, "archivedAt": "2026-03-10 04:00:00" }
}
```

**语义**：仅处理 `status='FINISHED'` 的学期；按「学期 + 归档类型」覆盖写，**幂等**；归档不影响历史查询。失败返回 `40943 学期尚未结束，不允许归档`。
