# 高校智慧教务选课平台 · 模块分工与建模任务清单

1. **每人独立负责 1–2 个模块**，自己完成该模块的**全部**需求、分析、设计建模及配套文档；**小组不合并文档，每人单独提交自己那部分**。
2. 交付物是**一条累积链**：大作业 N 要求提交**前 N-1 项全部成果的修正稿 + 第 N 项新成果**。所以**不要每份作业新建文件**，全程维护「一份 Word 文档 + 一套模型源文件」就地迭代。
3. 必须体现**三处同步**：概念层类图 ↔ 简单交互顺序图；说明层类图 ↔ 详细交互图；分析模型 ↔ 设计模型。
4. **建模图要截图直接贴进文档**，同时要交**建模附件源文件**。
5. 命名规则见第 4 节，**五个人的「系统名」必须完全一致**（建议统一用 `智慧教务选课平台`），否则大作业10 汇总时对不上。
6. 大作业8（实现模型：组件图 + 部署图）原文命名**不含模块名**，且组件/部署天然是系统级的——**先统一组件划分与部署节点，再各画自己模块那部分**。

## 2. 公共契约（开工前冻结，五个人的类图必须一致）

> 原则：**共享实体只由归属人定义，其他人在自己的类图里只画「引用」，不重复展开属性。** 跨模块调用一律走 `接口文档.md` 已有的 API 契约。

| 归属 | 冻结内容 |
| --- | --- |
| M1 | `RoleEnum`、登录态与鉴权契约（`UserContextHolder`、`@RequireRole`）、通知事件模型 `NoticeEvent` / `NoticeTypeEnum` |
| M2 | `SysUser` / `Student` / `Teacher` / `Major` / `Grade` / `AcademicClass` / `Classroom` / `Semester` |
| M3 | `Course` / `TeachingClass` / `Schedule` |
| M4 | `SelectionBatch` / `CourseSelection`（含 `waitlistNo`、`promotedAt`）、`SelectionStatusEnum`（含 `WAITING`） |
| M5 | `Score` / `Notification` |

**跨模块依赖（画交互图时可以直接引用，不要自己造）**

```text
M1 ──鉴权/通知事件──▶ 所有模块
M2 ──学生/教师/教室/学期基础数据──▶ M3、M4、M5

M4 ──批次状态变更/容量上调──▶ M1（通知）、M4（触发递补）
```

## 3. 每人任务卡

### 3.1 苏俊毅 —— M4 选课与候补（核心模块）

**功能范围**

- 选课批次：创建、修改、开启/提前关闭、状态流转（未开始/进行中/已结束）、批次开放教学班（添加/查询/移除）
- 学生选课：可选课程查询（按专业/年级/批次过滤）、课程详情、**选课 7 项校验**、选课记录生成
- 学生退课：批次时间校验、释放名额
- 候补：加入候补、候补位次、取消候补、退课自动递补、教务手动递补
- 高并发防超卖：容量不超卖、不产生重复记录、数据一致性

**用例清单**

| 用例 | 参与者 | 说明 |
| --- | --- | --- |
| 查询可选课程 | 学生 | 按专业/年级/批次/开放状态过滤 |
| 查看课程详情 | 学生 | 含剩余名额、是否可选 |
| 选课 | 学生 | 7 项校验：批次时间→重复→容量→时间冲突→年级→专业→学分上限 |
| 退课 | 学生 | 释放名额并触发候补递补 |
| 加入候补 | 学生 | 仅满员时允许 |
| 取消候补 | 学生 | 位次实时前移 |
| 查看我的候补列表 | 学生 | 含位次 |
| 手动触发递补 | 教务 | 异常场景补救 |
| 维护选课批次 | 教务 | 创建/修改/开关 |
| 维护批次教学班 | 教务 | 添加/移除 |

**9 项交付物与图表选题**

| 作业 | 交付物 | M4 的图/内容 |
| --- | --- | --- |
| 1 | 需求规格说明书 | 7 项校验规则、候补递补规则、非功能需求（并发） |
| 2 | 用例图 + 用例文档 | 用例图（学生/教务两个 Actor）；用例文档写「选课」「加入候补」的完整基本路径 + 异常路径 |
| 3 | 概念层类图 | `SelectionBatch`、`CourseSelection`、`TeachingClass`（引用）、`Student`（引用）；关联与多重性 |
| 4 | 简单交互图 | 顺序图（选课基本路径：学生→选课控制器→批次校验→容量校验→创建记录）；协作图由顺序图对应得出 |
| 5 | 说明层类图 | `CourseSelectionService`、`SelectionBatchService`、`WaitlistService` + 策略/工具类；责任分配（专家原则） |
| 6 | 详细交互图 | 顺序图（含 Redis/Lua 预扣名额、唯一索引兜底、事务边界） |
| 7 | 状态图 + 活动图 | 状态图：**选课记录**（已选/候补中/已退课）；活动图：**选课校验链**、**退课→候补递补**（泳道：学生｜系统｜缓存｜数据库） |
| 8 | 组件图 + 部署图 | 自己模块的组件（StudentSelectionController / WaitlistController / CourseSelectionService / WaitlistService）与所在节点 |
| 9 | 集成打包 | 上述 5 个定稿文件 |
