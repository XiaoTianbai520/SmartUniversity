## 1. 核心角色与权限边界

系统三类角色，权限严格隔离（对应 `RoleEnum`：ADMIN / TEACHER / STUDENT）。

### 1.1 学生（STUDENT）
登录后能：查询自己**有权限**的课程、查看课程详情、选课、退课、查看「我的课程」、查看个人课表、查看学分、查看**已发布**成绩、加入/取消**候补**、查看候补位次、查看站内通知。

**不能**：查询无权限课程、选无权限课程、退他人课程、查他人成绩、访问教师接口、访问教务接口。

### 1.2 教师（TEACHER）
登录后能：查看**自己负责**的教学班、查看教学班学生名单、录入/修改未发布成绩、发布成绩、导出教学班名单、导入成绩、查看成绩统计、查看通知。

**不能**：查看他人教学班、改他人成绩、管理学生/课程/批次。

### 1.3 教学管理员（ADMIN）
全局教学业务配置：管理学生/教师、专业/年级/班级/教室、课程、教学班、排课、选课批次的开关，以及 V1.1 的批量导入导出、手动候补递补、通知管理。

**铁律**：学生/教师身份一律从 `UserContextHolder` 取，不信任请求参数里的 `studentId` / `teacherId`；越权一律由后端再次校验拦截（见第 9 章）。

## 2. 总体业务主流程（端到端）

```text
教务维护基础数据（专业→年级→班级→学生/教师→教室→课程）
        ↓
创建教学班（分配教师/教室/时间 + 排课冲突检测）
        ↓
创建选课批次（时间窗 + 关联教学班）
        ↓
开启选课（批次进入「进行中」）
        ↓
学生查询有权限课程（专业+年级+批次范围过滤）
        ↓
学生选课 / 候补（13 步校验；满员走候补）
        ↓
生成「我的课程」+ 动态课表 + 学分累计
        ↓                       ┌─ 退课释放名额 → 触发候补递补
        ↓                       │
教师查看教学班与学生名单
        ↓
教师录入成绩（未发布）→ 修改（未发布）→ 发布
        ↓
学生查询已发布成绩 + 学分统计使用有效成绩
        ↓ （V1.1 增强）
系统通知贯穿：选课开启/结束、候补递补、课程调整、成绩发布
教务批量导入学生/教师/成绩、导出学生/名单
教师按教学班查看成绩统计（均分/及格率/分布）
```

## 3. 登录与身份识别

三类角色登录流程同构：账号存在性 → 密码校验 → 账号状态（启用/禁用）→ 生成 JWT 凭证 → 写入 `UserContext`。

- 登录成功后识别维度：用户 ID、学生/教师 ID、学号/工号、专业、年级、班级、角色。
- `AuthenticationInterceptor` + `@RequireRole` 在 Controller 层做**第一道**角色校验；Service 层再做**数据归属**校验（双重校验，不可省）。
- 普通学生/教师不能直连教务接口；过期令牌由拦截器拒绝。

## 4. 基础数据初始化（教务）

推荐顺序（层级依赖）：

```text
创建专业
   ↓
创建年级（grade_cohort）
   ↓
创建班级（academic_class，绑定专业+年级）
   ↓
创建学生（绑定专业/年级/班级 + 创建登录账号 + 角色 STUDENT）
   ↓
创建教师（创建登录账号 + 角色 TEACHER）
   ↓
创建教室（classroom）
```

这些基础数据就绪后，才进入课程与教学班管理。

## 5. 账号创建（学生 / 教师）

### 5.1 学生
教务填写信息 → 校验学号不重复 → 校验专业/年级/班级存在且匹配（班级须属对应专业+年级）→ 创建 `student` 记录 → 同步创建 `sys_user` 账号（角色 STUDENT）。异常拒绝项：学号重复、专业/年级/班级不存在、班级与专业或年级不匹配、登录账号重复。

### 5.2 教师
填写教师信息 → 校验工号不重复 → 创建 `teacher` 记录 → 同步创建 `sys_user` 账号（角色 TEACHER）。

## 6. 课程与教学班 + 排课冲突检测

**课程（course）** 与 **教学班（teaching_class）** 必须分开建模：课程是学校课程定义（学分、性质、适用专业/年级），教学班是一次实际授课（教师、教室、时间、容量、适用专业/年级明细）。

### 6.1 教学班创建
选课程 → 选学期 → 分配教师 → 选教室 → 星期/节次/教学周次 → 最大容量 → 适用专业+年级 → **排课冲突检测** → 保存。

### 6.2 排课冲突检测（双维度）
- **教师冲突**：同一教师当前学期已有教学班，时间（星期+节次+教学周）重叠 → 禁止保存。
- **教室冲突**：同一教室当前学期安排，时间重叠 → 禁止保存。

> 冲突判定口径（与 `CourseSelectionServiceImpl#isConflict` 一致）：同星期 且 教学周有交集 且 节次有交集，即视为冲突。

## 7. 选课批次（状态 / 时间窗）

批次（selection_batch）控制学生何时能选/退课，并通过 `selection_batch_class` 关联本批次开放的教学班集合。

### 7.1 状态机
```text
创建批次 → 未开始(NOT_STARTED)
   ↓（达到开始时间 / 教务开启）
进行中(IN_PROGRESS)
   ↓（达到结束时间 / 教务提前结束）
已结束(ENDED)
```
已结束批次不允许选课/退课。

### 7.2 时间校验规则
```text
选课开始时间 < 选课结束时间
若配置退课截止时间：退课截止时间 >= 选课开始时间
```

## 8. 学生可选课程查询（权限过滤）

最重要的权限流程之一。学生**只能看到自己有权限**的课程，后端三次过滤（与 `CourseSelectionServiceImpl` 一致）：

```text
获取当前登录学生 → 取专业/年级 → 取当前学期 → 取有效批次
   ↓
查该批次开放的教学班集合（selection_batch_class）
   ↓
按学生专业过滤（teaching_class_major）
   ↓
按学生年级过滤（teaching_class_grade）
   ↓
过滤未开放 / 非当前学期教学班
   ↓
返回可选课程列表
```

搜索语义：**先确定权限课程集合，再在集合内按名称搜**，绝不「先搜全部再过滤」，防止越权课程泄露。

## 9. 学生选课主流程（12 步校验）

`CourseSelectionServiceImpl#selectCourse`（已实现，与文档一致）按以下顺序执行，**任一步失败立即终止并抛出异常**：

```text
1. 身份校验：当前登录学生必须存在（UserContextHolder）
2. 教学班存在性校验
3. 学期校验：教学班须属当前学期
4. 批次校验：存在进行中批次，且教学班在该批次开放范围内（selection_batch_class）
5. 教学班状态校验：status.allowSelect() 为 true
6. 专业权限校验（teaching_class_major）
7. 年级权限校验（teaching_class_grade）
8. 重复选课校验：已存在 SELECTED → 重复选课（同一 student+class 唯一键兜底）
9. 时间冲突校验：与本人已选（SELECTED）课程逐条比较排课
10. 学分上限校验：(当前已选学分 + 目标课程学分) <= 学期上限
11. 容量校验：SELECTED 数 >= capacity → 课程已满；
        Redis 容量开关开启时走原子自增预扣减，否则以 DB 实时统计为准
12. 落库：无记录则新增（status=SELECTED），有记录则更新状态（详见 §10.6 边角）
```

> **容量控制开关**：`smart-university.selection.redis-deduct-enabled`。关闭时退化为纯 DB 事务，每次以 `COUNT(status=SELECTED)` 实时判定满员；开启时走 Redis 原子计数（带与 DB 不一致的 resync 兜底）。

## 10. 候补选课（V1.1）

### 10.1 状态模型
`course_selection.status` 三种值（见 `SelectionStatusEnum`）：

```text
SELECTED    已选（正式名额）
WAITING     候补中（占候补队列，不占正式名额）
WITHDRAWN   已退课 / 候补已取消 / 候补失效
```

状态流转：
```text
（无记录）─选课(有空位)─→ SELECTED ─退课/取消─→ WITHDRAWN
（无记录）─候补(已满)──→ WAITING ─取消候补─→ WITHDRAWN
                              └─递补成功─→ SELECTED
                              └─重校验不通过─→ WITHDRAWN（候补失效）
```
约束：同一学生、同一教学班在 `course_selection` 仅一条记录（唯一键 `uk_selection_student_class`），不可能「既已选又候补」。

### 10.2 加入候补（joinWaitlist，与 §9 校验链对齐）
```text
身份 → 教学班/学期 → 批次/状态 → 专业/年级 → 重复(SELECTED/WAITING) → 时间冲突 → 学分上限
   ↓
容量校验：必须「已满」(SELECTED >= capacity)，未满拒绝并提示直接选课
   ↓
waitlist_no = 该班当前最大候补序号 + 1（退课后重候补不插队）
   ↓
写入/更新 status = WAITING → 返回候补位次
```
要点：候选队列存在意义是「名额争抢」，有空位必须引导直接选课；候补不占 Redis 容量计数。

### 10.3 候补位次查询
位次 =（同班 `waitlist_no` 小于本人且 `status=WAITING` 的记录数）+ 1；同时返回候补总人数、已选人数、容量。取消后 `waitlist_no` 保留不清零，**位次实时计算天然跳过已取消记录**（不在 SQL 重排，避免并发行锁）。

### 10.4 取消候补
校验归属（记录须属当前学生）→ 校验状态为 WAITING → 校验在批次时间窗内（批次结束不允许变更）→ 置 WITHDRAWN，`waitlist_no` 保留。

### 10.5 候补递补（核心，tryPromote）
触发点（三个）：

| 触发场景 | 触发位置 | 事务要求 |
|---|---|---|
| 正式选课学生退课释放名额 | `CourseSelectionServiceImpl.withdrawCourse` | 与退课同事务（名额释放与占用原子） |
| 教务上调教学班容量释放名额 | `TeachingClassServiceImpl`（**事务提交后回调 afterCommit**） | 必须 afterCommit，否则共享事务被标 rollback-only 会连带回滚容量调整 |
| 教务手动触发递补 | `AdminWaitlistController`（新增接口） | 独立调用 |

统一方法：`WaitlistService.tryPromote(teachingClassId)`。流程：
```text
释放名额 → 剩余可用 = capacity - COUNT(SELECTED)
   ↓ <=0 直接结束
取候补队首（status=WAITING，waitlist_no 最小）
   ↓
重跑选课全量校验（批次窗/状态/范围、专业、年级、时间冲突、学分上限）
   ↓
不通过 → 标记 WITHDRAWN（候补失效），continue 取下一条
通过   → status=SELECTED，扣减 Redis 容量计数，发布 WAITLIST_PROMOTED 通知
   ↓
继续尝试下一条，直到名额占满或队列清空（必然收敛，不无限循环）
```
> 上调容量走 `afterCommit` 回调的原因：若同步调用 `tryPromote`（PROPAGATION_REQUIRED 加入同一物理事务），递补抛未捕获异常会把共享事务标 rollback-only，导致纯配置性质的「容量上调」连带回滚。故改用 `TransactionSynchronizationManager.registerSynchronization(afterCommit)` 隔离（代码 `TeachingClassServiceImpl#promoteWaitlistAfterCommit` 已落实，且仅在 capacity 上调时触发）。

### 10.6 选课/候补的共用更新分支（边角提示）
`selectCourse` 在「已存在 WAITING 记录」时走 update 分支直接转 SELECTED（不经候补路径）。正常流程由 `tryPromote` 完成递补，但该分支意味着一个仍处于 WAITING 的学生在班级有空位时直接选课也会被允许——属可接受的边角行为，文档此前未显式覆盖，已记入 §20 核对表。

### 10.7 我的课程中的候补展示
`StudentSelectionRespDTO` 返回 `status`（枚举 name，V1.1 自动含 WAITING）+ 补充 `waitlistNo` / `waitlistRank` / `waitingCount`。

## 11. 学生退课流程（含候补递补触发）

```text
学生进入「我的课程」→ 选已选课程 → 退课
   ↓
取当前学生 → 查选课记录 → 校验归属（记录 studentId == 当前学生）
   ↓
校验状态为 SELECTED（WITHDRAWN 不可再退）
   ↓
退课时间校验：当前 <= 批次退课截止时间
   ↓
更新 status=WITHDRAWN，教学班容量 -1（Redis 回补）
   ↓
tryPromote(teachingClassId) 尝试递补（失败仅记日志，不阻断退课主流程）
```
V1.0 不触发递补；V1.1 退课释放名额后必须尝试递补（见 §10.5）。

## 12. 我的课程 / 课表 / 学分

- **我的课程**：按当前学期查选课记录（含 SELECTED / WAITING 展示），关联教学班+课程+排课。
- **课表**：**不单独维护课表数据**，由当前学期有效（SELECTED）选课记录动态生成（按星期/节次排序），避免与选课数据双份不一致。
- **学分**：按当前学期已选（SELECTED）课程统计，区分必修/专业选修/公共选修；已完成总学分由成绩数据汇总。

---

## 13. 教师教学班 / 名单 / 成绩

### 13.1 我的教学班
查询条件**必须**带当前登录教师 ID（从 `UserContextHolder` 取），按当前学期过滤。

### 13.2 学生名单
点教学班 → 校验 `teacher_id == 当前教师` → 查 SELECTED 选课记录 → 关联学生信息返回。

### 13.3 成绩生命周期
```text
录入成绩（status=未发布 UNPUBLISHED）
   ↓
修改成绩（仅未发布允许；已发布默认拒绝）
   ↓
发布成绩（status=已发布 PUBLISHED）→ 事务提交后触发 SCORE_PUBLISHED 通知
```
- 成绩格式校验：`0 <= 成绩 <= 100`，非法拒绝。
- 学生查询成绩：**仅查 status=已发布**，不能查他人、不能查未发布。

## 14. 系统通知（V1.1）

### 14.1 通知类型（`NoticeTypeEnum`）
```text
SELECTION_START     选课开始  → 有资格学生（按角色）
SELECTION_END       选课结束  → 有资格学生（按角色）
WAITLIST_PROMOTED   候补成功  → 被递补学生本人（按选课记录）
COURSE_ADJUSTED     课程调整  → 该班已选学生（bizId 传 null，每次都通知）
SCORE_PUBLISHED     成绩发布  → 该班已发布成绩学生
```

### 14.2 数据模型
**一人一条**站内信（`notification`），群发时批量插入多份。唯一键 `uk_notice_dedup(notice_type, biz_id, receiver_user_id)` 天然幂等。

### 14.3 产生流程（事件解耦）
```text
业务模块发生事件 → NoticeEventPublisher.publish(NoticeEvent)
   ↓（携带已解析好的接收人 user_id 列表）
@TransactionalEventListener(AFTER_COMMIT, fallbackExecution=true)
   ↓
NotificationEventListener 为每个接收人构造 NotificationDO
   ↓
bizId != null 时命中 uk_notice_dedup 跳过；bizId == null 时直接插入（不查重）
   ↓
每位接收人独立 REQUIRES_NEW 事务落库（单条失败不影响其他）
```
- 接收人解析 `NoticeTargetResolver`：`listUserIdsByRole` / `listUserIdsByTeachingClassId` / `listUserIdsBySelectionIds`。
- 定时任务 `SelectionBatchNoticeTask`（@Scheduled fixedDelay=60s）扫描批次开始/结束，发 SELECTION_START/END（bizId=batchId 去重）。

### 14.4 通知消费（接收人本人）
```text
登录 → GET /api/v1/notifications/unread-count（角标）
     → GET /api/v1/notifications（分页列表）
     → PUT /api/v1/notifications/{id}/read（单条已读）
     → PUT /api/v1/notifications/read-all（全部已读）
```
权限：只能查自己 user_id 的通知，**禁止**路径参数指定他人。

## 15. 批量导入导出（V1.1）

依赖 **Apache POI 5.4.1**，仅支持 `.xlsx`（`.xls` 直接拒绝）；模板与解析共用同一份列定义（避免漂移）。导入**禁止引入消息队列/Redis**，同步执行、即时看结果。

| 能力 | 入口 | 要点 |
|---|---|---|
| 教务导入学生 | `AdminExcelController` | 列：学号/姓名/专业编号/年级名称/班级编号/初始密码；复用 V1.0 账号创建逻辑 |
| 教务导入教师 | `AdminExcelController` | 列：教师编号/姓名/职称/初始密码 |
| 教务导出学生 | `AdminExcelController` | 按筛选条件（专业/年级/班级/关键字），关联专业/年级/班级名称 |
| 教师导出名单 | `TeacherExcelController` | 归属校验 teacher_id，仅 SELECTED 记录 |
| 教师导入成绩 | `TeacherExcelController` | 列：学号/姓名/成绩；校验归属+SELECTED、0~100、已发布拒绝覆盖 |

**处理原则**：逐行独立 try/catch、**外层不加 `@Transactional`**，单行脏数据记录原因继续，返回 `ImportResultRespDTO{totalCount, successCount, failCount, failList[]}`。

## 16. 教师成绩统计（V1.1）

以**单个教学班**为单元，在 **Service 层内存聚合**（数据量级几十~几百条，足够；V2.0 再转 SQL/宽表）。

统计项（`ScoreStatisticsServiceImpl`）：
| 指标 | 口径 |
|---|---|
| 统计人数 | 已录入成绩记录数（scoredCount） |
| 未录入人数 | SELECTED 数 − scoredCount |
| 平均分 / 最高 / 最低 | 无数据返回 0（"0.0"），保留一位小数 |
| 及格率 | 成绩 >= 60 人数 / 已录入人数（分母 0 返回 0） |
| 优秀率 | 成绩 >= 85 人数 / 已录入人数（分母 0 返回 0） |
| 成绩分布 | 五段：<60、60-69、70-79、80-89、90-100，各段人数与占比 |

常量：`PASS_SCORE_LINE=60`、`EXCELLENT_SCORE_LINE=85`。分母为 0 必须返回 0，不允许除零。

## 17. 核心状态机总览

```text
账号状态(sys_user)：    启用 ──禁用──→ 禁用
选课批次(batch)：       未开始 → 进行中 → 已结束
选课记录(selection)：   已选(SELECTED) ⇄ 已退课(WITHDRAWN)
                       候补(WAITING) → 已退课(WITHDRAWN) / 已选(SELECTED)
成绩(score)：           未发布(UNPUBLISHED) → 已发布(PUBLISHED)
```

## 18. 关键业务异常（节选）

- **登录**：账号不存在 / 密码错误 / 账号禁用 / 令牌过期。
- **选课**：非选课时间 / 课程不存在 / 未开放 / 专业不符 / 年级不符 / 重复选课 / 时间冲突 / 学分超限 / 课程已满 / 候补名额可用（未满时拒绝候补）。
- **退课**：不允许退课（过截止）/ 记录不存在 / 非本人 / 已退过。
- **教学班**：教师时间冲突 / 教室时间冲突 / 容量不合法。
- **成绩**：无教学班权限 / 学生不属本班 / 格式错误 / 已发布重复修改 / 查未发布成绩。
- **通知**：bizId=null 不查重（COURSE_ADJUSTED 每次都通知，可接受重复）。

## 20. 代码核对结论（文档 vs 实现）

> 核对范围：后端源码 `src/main/java/com/smart/university`。结论：V1.0 与 V1.1 四个增强模块均已落地，核心设计（状态模型、通知解耦、导入逐行、统计聚合）与文档一致。发现 **1 处真实语义张力 + 3 处实现方式偏差**。

### 20.1 一致项（已验证）

| 设计点                                                       | 代码位置                                                     |
| ------------------------------------------------------------ | ------------------------------------------------------------ |
| 选课 13 步校验（身份→教学班→学期→批次→状态→专业→年级→重复→时间冲突→学分→容量→落库+消息） | `CourseSelectionServiceImpl#selectCourse`                    |
| 候补须「名额已满」才开放，未满拒绝引导直选                   | `WaitlistServiceImpl#joinWaitlist`                           |
| 退课释放名额后触发 `tryPromote`                              | `CourseSelectionServiceImpl#withdrawCourse`                  |
| 上调容量走 `afterCommit` 回调（非同步）                      | `TeachingClassServiceImpl#promoteWaitlistAfterCommit`        |
| 递补重跑全量校验，不通过标 WITHDRAWN 继续下一条，必然收敛    | `WaitlistServiceImpl#tryPromote` / `#promoteWaitlistSelection` |
| 通知用 `@TransactionalEventListener(AFTER_COMMIT, fallbackExecution=true)` 解耦 | `NotificationEventListener`                                  |
| `uk_notice_dedup` 幂等；bizId=null 跳过查重（COURSE_ADJUSTED 传 null） | `NotificationEventListener` + `V1.1_数据库增量设计.sql`      |
| 导入逐行独立事务、不引 MQ/Redis、`.xls` 拒绝、成绩已发布拒绝覆盖、0~100 | `ImportExportServiceImpl` / `ExcelParseUtil`                 |
| 成绩统计单班内存聚合、五段分布、及格线 60 / 优秀线 85、分母 0 返回 0 | `ScoreStatisticsServiceImpl`                                 |
| 五类通知类型、三态批次、三态选课记录与枚举完全对应           | `NoticeTypeEnum` / `SelectionBatchStatusEnum` / `SelectionStatusEnum` |

### 20.2 分歧 / 风险（建议处理）

| #    | 模块 | 类型                       | 说明                                                         | 位置                                                    |
| ---- | ---- | -------------------------- | ------------------------------------------------------------ | ------------------------------------------------------- |
| 1    | 候补 | **语义张力（建议修）**     | `withdrawCourse` 与 `tryPromote` 同属一个物理事务（PROPAGATION_REQUIRED），但代码用 `try { tryPromote } catch { log }` 包裹并注释「递补失败不影响退课」。若 `tryPromote` 抛**未被其内部捕获**的异常，会把共享事务标 rollback-only，提交时整体回滚（退课也会丢失），与文档「递补同事务、异常整体回滚」措辞冲突。正常路径因循环内已吞掉 `BizException` 不会触发，但边界异常仍可能连带回滚；且回滚时 Redis 已 -1 但 DB 未变会出现 1 条缓存漂移。 | `CourseSelectionServiceImpl` 第 154–183 行              |
| 2    | 通知 | **实现方式偏差（可接受）** | 文档字面「批量插入命中唯一键后逐条降级为单条插入」；代码实际从一开始就是「逐接收人单条 REQUIRES_NEW 插入 + 预查重」。目标（单条失败不连累其他、幂等）完全达成，更稳健，仅措辞不同。 | `NotificationEventListener`                             |
| 3    | 候补 | **轻微行为（提示）**       | 递补重校验列表未显式含「重复」项，但由 `uk_selection_student_class` 唯一约束结构性保证（同生同班不可能 SELECTED 冲突），可接受。 | `WaitlistServiceImpl#promoteWaitlistSelection`          |
| 4    | 候补 | **边角行为（提示）**       | 学生已有 WAITING 记录时直接调 `selectCourse` 会走 update 分支转 SELECTED（非候补递补路径），文档此前未显式覆盖。 | `CourseSelectionServiceImpl#selectCourse` 第 115–142 行 |

**针对 #1 的建议（二选一，需明确其一）**：

- 方案 A：让退课场景的 `tryPromote` 真正独立（改走 `REQUIRES_NEW` 或 afterCommit 调用），使「递补失败不影响退课」成立；
- 方案 B：在本文档/接口文档中明确「退课主路径不保证递补与退课原子，递补失败仅记日志、由教务手动递补接口兜底」，消除措辞与实现的歧义。

### 20.3 落地状态提示（部署侧，非业务）

- 据项目记忆，生产库（192.168.1.102 / `edu_course_selection`）仍停留在 V1.0 schema，**V1.1 增量 SQL（`docs/V1.1_数据库增量设计.sql`，含 `notification` 表与 `uk_notice_dedup`、候补 `status` 扩展、成绩/导入导出相关字段）尚未执行**，上线前须补跑。
